逐层量化：
是单卡执行每一个decode layer，包括像load、smooth、量化、save、offload。解决的是超大模型无法量化的问题

DP：
切分数据，每个rank执行一份数据，是数据并行
spawn启动多进程，每个进程绑定一个npu，distributed 创建 hccl
根据算法不同，选择all reduce还是all gather，如果是min max就是all reduce得到全局的min max就行。如果要全量激活就all gather
但是后续计算每个卡都在做同样的计算，不过相对来说开销很小，为了保持一致性，主要聚焦的还是节省下来的前向数据统计耗时
保存也是并行的

DTS：
DTS是程序启动DP后的自动选择
任务并行，比如data-free的情况下，dp没有用，可以把每个rank处理不同的linear，这时候每个卡做各自做计算

同步机制：
先同步owner map，也就是每个卡把自己处理的linear gather起来
一级同步：普通的linear任务，只有weight这样的parameter计算
二级同步：特殊的量化算法任务，有自定义的数据结构，比如awq有ratio，autoround有偏移值
三级同步：跨模块的任务，比如smooth，要做融合的，这个是最顶层的

权重转换：
多进程open权重，这时候还没加加载到内存，就是读了个head
在线程中根据key，去get tensor读取每个weight到内存中进行计算，这时候线程就有用了，因为有IO开销
不然会有GIL，python规定进程内线程必须CPU串行
除非有些torch算子的内部c++实现有多线程功能，OPENMP参数，set_num_thread()函数
竞品llm-compressor：cpu是纯串行，很慢。有多线程机制，但是结合GPU运行

hadamard矩阵是怎么计算的？
旋转矩阵Q=1/根号n * H * D，因为每一行的长度是根号n，所以需要归一化，归一化才是打散的关键。hadmard矩阵是为了混合每个通道的数据
先确定size，和要旋转的那一维一致，比如hidden_size、head_dim
D：随机种子seed生成+1和-1的对角矩阵，需要随机是因为避免输入和hadmard的固定模式对齐，导致旋转无效
1.用walsh快速推导hadamard矩阵
[1, 1]
[1,-1]
2.FWHT是直接将目标矩阵快速做旋转，跳过生成旋转矩阵这个过程了
非2次幂的，拆分成预先生成的非二次幂hadamard和二次幂的相乘（butterfly计算，比walsh推导性能更好）
如果是非常大的维度：
1.可以两个小矩阵相乘Kronecker 分解。比如down的行size是i_h（很大），分解成i_h = m * n，然后把这一行reshape成一个m * n的矩阵，这样就可以用两个m*m（行旋转）和n*n（列旋转）的矩阵来做旋转
2.Block Hadamard。原tensor分块，旋转矩阵对角化，分成块状处理
3.FWHT。快速推导旋转矩阵计算，主要靠不断执行(a, b) -> (a+b, a-b)

AWQ：
先计算每个通道的平均值=每个通道的scale，scale会有一个power操作，ratio是针对power的参数
枚举ratio，0.05一个步长，和scale逐元素相乘，计算mse

SSZ：
1.原始scale、offset，计算得到q
2.固定q，最小二乘计算scale、offset
3.得到新q，执行2
4.不断循环，直到收敛

GPTQ：
是per channel，一个列做完量化了，补偿到其他列
残差，计算误差后，补偿到未量化元素中，很耗时

msAgent：
先做一次敏感层分析，上界：敏感层全回退，下界：不回退
二分搜索最小达标的点，然后继续摸高，减少回退or换抑制策略
subagent：配置prompt、skills、检查清单

敏感层分析：
layer层级的：
mse_layer_wise：每一层跑一遍伪量化前向，然后跑一遍浮点前向，比较两者的mse，最后传给下一层的输出是浮点的输出【适合初筛，开销小，模型结构非标准也可以】
mse_model_wise：有几个decodelayer就跑几遍，第一个分支就跑全浮点，第二个分支就跑量化block.0的，但是其他block是浮点，以此类推，算得是跑完所有layer的最终误差，但是每次只有一个block量化了【对初筛的二次确认】
linear层级的：
只是统计每一个linear的输入激活x，不做量化，主要看激活的动态范围、极值

量化收益在推理时怎么拿到？
首先比较直观的是数据的显存占用减少了

计算量的层面分析（prefill）、访存带宽层面分析（decode）、并行层面分析（ep并行）
1.是否能低精度load权重，不然显存都没法省
2.硬件是否支持原生低精度计算，不然要反量化成bf16，此处有开销，且bf16还会反存回显存，显存收益也没有了，如果做了融合，可能还会有点显存收益或者带宽收益（decode阶段）-------- 910上w4a8采用msd算法，将a的8bit拆成2个4bit和w4计算，会有pack的开销，a = 16ah + al + 8
3.是否有反量化矩阵乘融合算子，减少反量化的写回开销
4.动态量化会有一定开销，因为要在线计算激活scale等
5.通信收益：首先权重量化了之后，每个卡上的EP可以放的更多了，并行度更大了，然后通信交互的是低比特的数据，也能提高带宽
6.prefill阶段是计算密集型，更看重硬件是否支持低精度计算。decode阶段是memory-bound，读取带宽减少可以提升性能
7.为什么达不到理论倍数：不是所有层都做量化，有scale等数据，需要反量化，硬件没有原生支持低精度计算
8.是否attention成为瓶颈，可以做fa3，或者kv cache量化

w4a8计算收益：msd多尺度展开算法（Multi-Scale Decomposition），把w4a8的a拆成两个4，公式：16ah+al+8，从而获得计算收益


FA3和KV CACHE量化
fa3_quant：量化 Attention 中间的 【Q/K/V 激活】，面向 【MLA/DeepSeek】【mla存的kv是低维的ckv和k_pe，q也是q_nope和q_pe两个】
【q per-token动态（保精度），k v per-head静态（保带宽，不然cache里要存scale）】
deepseek的mla插桩点是：`q_nope` / `ckv`【8bit存储，但是对应的k_pe是bf16存储】
【prefill阶段主要是为了存fp8的kv cache，实际计算还是用bf16，decode阶段做了融合算子，在内部完成8bit计算后得到fp32的结果和k、q_pe的fp32结果求和】
【原因在于p和d的qk计算中qk的维度不一样，prefill的维度是qk_nope_head_dim（小一点）】
【为了节省cache大小，存的是共享的latent kv cache（因为做了权重吸收，不同head在权重中体现），decode阶段读的k是kv_lora_rank（大一点，对这个维度做量化的）】

dynamic_cache：量化写入 DynamicCache 的 K/V，目标是降低 KV Cache 显存；
【per-channel】
【因为q是浮点，所以在prefill阶段直接用的原始bf16计算，只是存了8bit的。在decode阶段会做算子融合，dequant步骤在算子内部】

为什么kv cache用per channel，而fa3里的kv用per head，因为channel粒度更小精度更高，fa3的kv主要是量化计算部分，不管存储，per head更符合计算时的流程

DSpark量化：
DSpark原理：并行输出多个token，然后markov head会做轻量的顺序依赖（修正logits），confidence sceduling会预测置信度，低的就砍掉

首先确认背景，V4主模型是做了旋转的，且dspark mtp中的embed和head是共用主模型的权重
DSpark需要接收两个输入，一个是用来prefill构造kv cache的main hidden，一个是普通的经过主模型head输出的output
假设有两种方案，一个是mtp就不旋转
1.main hidden需要经过main proj和main norm，然后进入attn，计算wkv和kv norm。由于策略是不旋转，我需要把带旋转的main_hidden反旋回来，那就需要main proj做一个右旋来抵消
2.但是output（不带旋转的）正常经过embed之后，由于embed是共享主模型的，所以是旋转过的，这时候就有矛盾了，所以策略是复制主模型没旋转前的embed和head，保证output这条decode分支也不带旋转
还有一个是如果mtp精度不行，需要QuaRot
1.难点在于如何处理wkv，因为在prefill阶段，wkv接收的是不带旋转的，但是在decode阶段接收的x是带旋转的，所以这里只能复制一份wkv。其他保持一致

wan2.2量化的难点：
激活分布动态变化大【动态量化】，异常值敏感【算法选择ceilX、mse round】、attention敏感【在线旋转】，前层极度敏感【回退混合量化】，显存压力大【逐层量化】
1.采用激活的动态量化，因为高噪低噪结构、还分t2v、i2v、ti2v，多模态数据输入差异大，构造校准集采用静态scale的难度大且效果不好。
方案：线性层激活使用per block的动态量化，32个元素计算scale，采用w4a4混w8a8，attention部分采用fp8 per token混mxfp4 per block
2.对异常值极度敏感
方案：量化scale的计算粒度减小，32个元素。算法的选择，4bit采用ceilX，8bit采用mse round
3.attention部分敏感
方案：采用在线旋转+混合量化，离线保存hadamard矩阵，在线对Q、K做QuaRot，然后再做FA3量化
4.不同层量化敏感度差异大
方案：敏感层分析，前五个dit block回退到mxfp8，第0层的self attention用fp8
5.双专家，默认是81帧1080p，40个扩散步，对npu的显存要求高
方案：逐层量化
6.vbench测评耗时大
方案：k-means采样小数据集
补充：为什么不量化cross-attention？因为占比没有self-attention那么大，且语义敏感


ParetoQ：
准确率和量化是一个tradoff，得确认什么位宽最合适，需要统一的低比特量化框架，比较1bit、1.58bit、2bit、3bit、4bit
1.58bit：有3个状态需要表示，负数、0、正数，所以是log2 3，所以约等于1.58bit的信息量。硬件上还是不支持
scaling law原始：和参数量、训练数据、量化位宽三个有关，论文提出还与量化策略、量化函数有关
最终量化策略：90%全精度预训练+10%QAT微调
保存的是bf16+scale，所以还需要离线做一波转换+pack
固定了量化策略，就搜索量化函数：主要是确定映射的量化网格分布，比如2bit能表示4位【-0.75α，-0.25α，0.25α，0.75α】，α是QAT阶段学习出来的参数

Qwen3.5 mxfp8量化乱码
2^-127次方归零，计算scale导致出现inf
2^-127对于bf16来说在npu上subnormal非正规数（最小正规数为2^-126），950上直接flush to zero了
然后作为除数，共享指数算出来就是nan
修改算子侧：在碰到非正规数做power时，先补偿2^23次方，后续计算完再减掉

对称int8量化代码：
abs_max = max(abs(x_min), abs(x_max))
scale = abs_max / 127
quantized = clip(round(x / scale), -127, 127)
dequantized = quantized * scale

非对称int8量化代码：
scale = (x_max - x_min) / (127 - (-128))
zero_point = round(-x_min / scale)
quantized = clip(round(x / scale + zero_point), -128, 127)
dequantized = scale * (quantized - zero_point)

mxfp8量化代码：
block_max = max(abs(block))
nv：shared_exp = ceil(log2(block_max / 448))
ocp：shared_exp = floor(log2(block_max)) - 8
缩放：
y = x / 2 ^ shared_exp
计算私有指数：
private_exp = floor(log2(y))
计算尾数：
尾数部分 = y / 2 ^ private_exp
舍入映射：
e4m3_value = M3(尾数部分) * 2 ^ private_exp

dequant：
dequant = e4m3_value × 2 ^ shared_exp
